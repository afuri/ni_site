# Общие олимпиады и PDF для участника

## Настройка олимпиады

1. В админке создайте олимпиаду, выберите классы (включая `0`) и
   включите «Общая олимпиада без пула». Несколько классов разрешены.
2. Задайте начало и окончание проведения. Для пяти дней укажите соответствующий
   интервал; публикация сама даты не переносит. Длительность — от 1 до 360 минут.
3. Добавьте задания и сохраните черновик.
4. Подготовьте PDF вне сервиса либо один раз через существующую кнопку «PDF».
   Проверьте файл вручную: никаких правильных ответов и соответствие заданиям
   онлайн-версии. Загрузите его через отдельную кнопку «PDF для участника» в строке
   олимпиады (до 20 МБ). Сервер проверяет размер, расширение, MIME и сигнатуру/
   окончание файла; он не проверяет содержание на наличие ответов.
5. Через «Скачать для проверки» проверьте именно загруженный файл. Затем публикуйте.

Кнопки PDF открывают документ в новой вкладке текущего браузера. Оттуда можно
сохранить или распечатать файл средствами просмотрщика. Если браузер блокирует
новую вкладку, разрешите её открытие для сайта и повторите действие.

Общая олимпиада появляется в блоке с котом для всех выбранных классов, вместе с
описанием. Пул для неё создавать нельзя. До начала действует таймер. «Начать»
использует прежнее окно с инструкцией на главной; PDF не запускает попытку.
Одна попытка на олимпиаду и одна активная попытка на пользователя сохраняются.

PDF доступен до старта в период проведения, а также до дедлайна активной попытки,
даже если период проведения уже закончился. После завершения/истечения попытки
PDF участнику больше не выдаётся.
В блоке с котом завершённые/истёкшие работы скрыты; их результаты остаются в
«Мой сезон» и «Результаты», без кнопки PDF.
Активная общая работа остаётся с «Продолжить» и PDF
до дедлайна. API требует действующую ученическую сессию и подтверждённый email.

После публикации PDF нельзя заменить или отключить. Если олимпиада ещё не
использовалась, верните её в черновик существующей командой. Изменение состава
заданий отключает прежний PDF; загрузите актуальный файл заново. Копия олимпиады
сохраняет общий режим, но создаётся без PDF. Редактирование текста самих заданий
в банке до публикации требует ручной проверки актуальности подготовленного PDF.

## Хранилище

Файлы не попадают в публичный bucket изображений. Используется отдельный
`STORAGE_PRIVATE_BUCKET`, по умолчанию `<STORAGE_BUCKET>-private`
(для стандартной конфигурации — `ni-site-private`). Не назначайте этому bucket
политику анонимного чтения. Его нельзя настроить на имя публичного bucket.

Если bucket отсутствует, первый upload создаст его с приватными настройками.
Учётной записи storage нужны права создания bucket либо bucket должен быть
создан оператором заранее, а также права `PutObject`/`GetObject` в нём.
В endpoint/environment остаются существующие настройки MinIO/S3. Отдельная
переменная `STORAGE_PRIVATE_BUCKET` нужна только для нестандартного имени.

API не возвращает ключи или постоянные ссылки участнику: отдаёт файл потоком
после проверки прав и серверного времени, с `Cache-Control: private, no-store`.
Уже скачанную копию отозвать невозможно. Старые версии файлов при замене/
отключении остаются приватными и не выдаются API; сохраняйте bucket вместе с
резервными копиями БД. Автоматической физической очистки этих версий нет.

На reverse proxy для upload разрешите размер запроса больше 20 МБ с учётом
multipart (например, `client_max_body_size 21m;` в соответствующем nginx location).
Остальные лимиты изображений и ZIP не менялись.

## Включение локально

Новая миграция: `f2c7a9d1e603`, предыдущая: `a8b3d5f7c901`. Она добавляет два
поля и ограничение, старые олимпиады получают `is_standalone=false`, PDF — `NULL`.
В рамках разработки проверена на отдельной чистой БД, затем downgrade/upgrade
с сохранением синтетической старой олимпиады. 4 октября 2026 года основная локальная
БД также обновлена до `f2c7a9d1e603` после резервного копирования; записи сохранены.

После резервной копии из корня проекта:

```bash
docker compose -f docker-compose.local.yml --profile worker stop --timeout 120 api worker beat
docker compose -f docker-compose.local.yml --profile worker build api worker beat
docker compose -f docker-compose.local.yml run --rm --no-deps api alembic -c /app/alembic.ini upgrade head
docker compose -f docker-compose.local.yml --profile worker up -d --no-deps api worker beat
npm --prefix frontend run build:app
npm --prefix frontend run build:admin
```

Production использует свой compose
и существующий порядок deployment; нужны новая сборка API, миграция и обе
frontend-сборки. Пулы, существующие попытки и результаты миграция не меняет.

## Ручная проверка

1. Опубликованная общая олимпиада класса 0 видна дошкольнику, но не школьнику
   другого класса; неопубликованная не видна никому из участников.
2. До начала нет скачивания PDF/старта; в период проведения доступны обе кнопки.
3. Нажать «Скачать PDF»: документ открывается в новой вкладке. Проверить, что
   попытка ещё не появилась и таймер не начался.
4. Начать работу: «Продолжить» активно, другие старты заблокированы.
5. Закрыть период в отдельном тестовом окружении при живой попытке: продолжение
   и PDF ещё доступны. После дедлайна исчезают, повторная попытка не создаётся.
6. После завершения работа остаётся в сезоне/результатах; ответы/дипломы работают
   по прежним правилам публикации результатов.
7. Ученику и учителю недоступен admin-upload; обычной олимпиаде нельзя прикрепить
   PDF участника; общую нельзя включить даже в неактивный пул.

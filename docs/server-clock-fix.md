# Доступность олимпиады по серверному времени

Исправление убирает зависимость кнопки «Начать» от даты компьютера. Схема БД, миграции, распределение вариантов и условия допуска остаются прежними.

## Что изменено

- Блок с котом использует общий отсчёт времени сервера. По нему определяются начало/окончание окна, обратный отсчёт, дедлайн активной попытки и доступность PDF.
- Исправлена также повторная проверка времени на главной странице после перехода из кабинета: инструкция открывается по тому же источнику времени. Иначе исправленная кнопка могла привести к отказу на следующем экране.
- Если опорное время получить не удалось, карточка сохраняется, старт блокируется с сообщением о проверке времени и возможностью повторить её. Отсутствие синхронизации не превращается в сообщение о завершении олимпиады.
- Окончательные проверки начала/продолжения и приёма ответов по-прежнему выполняет сервер.

## Нагрузка

Все ответы /api/v1/ получают X-Server-Time: UTC Unix timestamp в миллисекундах на момент отправки заголовков. Формат существующих JSON-ответов не меняется. Заголовок добавлен в Access-Control-Expose-Headers, не меняя разрешения на доступ с других origins.

Общий API-клиент считывает время из уже выполняющихся запросов, включая загрузку профиля и списка олимпиад. После получения опорного времени секунды вычисляются через performance.now, без сетевых запросов. Изменение системной даты не меняет этот отсчёт. Ответы с положительным HTTP Age не используются как свежие образцы времени; отменённые запросы также не обновляют часы.

Резервный GET /api/v1/time используется при отсутствии свежего образца или после длительного отсутствия/сна, при возврате во вкладку. Он не требует входа, сессии БД, Redis или записи аудита. Ответ содержит server_now в UTC и Cache-Control: no-store. Этот технический GET исключён из middleware аудита и Redis-лимитов; остальные маршруты сохраняют прежние проверки.

В одной вкладке одновременно выполняется только один резервный запрос; все компоненты используют его результат. Повторные попытки ограничены одним запуском за 60 секунд по монотонному таймеру. Таймаут резервного запроса — 5 секунд. Автоматического периодического опроса сервера нет. Свежие обычные ответы API обновляют опорное время без отдельной синхронизации.

Локальный секундный таймер работает только при наличии олимпиад или активной попытки, пока вкладка видима. После долгого отсутствия синхронизация учитывает также признаки сна: некоторые браузеры приостанавливают performance.now во время сна. Системная дата используется исключительно для обнаружения такого расхождения, не для разрешения старта.

Новые переменные окружения и библиотеки не требуются. Общие часы хранятся в памяти вкладки и не восстанавливаются из localStorage.

## Применение на сервере

Сначала обновить API, затем опубликовать основной frontend. Новый frontend должен получить X-Server-Time либо ответ /api/v1/time.

Если одновременно применяются ранее подготовленные исправления хранилища и аудита:

```bash
cd /opt/ni_site
docker compose build api worker beat
docker compose up -d --no-deps --force-recreate api worker beat
```

Для отдельного исправления времени достаточно пересборки/пересоздания API. Команды обновления основного frontend:

```bash
cd /opt/ni_site/frontend
npm ci
npm run build:app
```

Опубликовать frontend/apps/main/dist в действующую директорию Nginx по deploy.md. Если одновременно публикуются ранее подготовленные изменения админки, выполнить также npm run build:admin и обновить её dist.

Проверить доступность часов:

```bash
curl -i https://www.nevsky-integral.ru/api/v1/time
```

Ожидается HTTP 200, X-Server-Time, Cache-Control: no-store и JSON server_now с UTC-временем. Если Nginx использует фильтрацию заголовков, X-Server-Time должен доходить до браузера. После публикации обновить открытые страницы кабинета.

## Проверки

Проверено, что дата браузера на день назад/вперёд не меняет доступность работы, а переход «Начать» → инструкция → подтверждение старта работает даже при дате браузера на годы вперёд. При обычных ответах API этот сценарий не делает запросов /time.

Проверены объединение одновременных резервных запросов, отсутствие секундного сетевого опроса, ограничение повторов, восстановление после долгого отсутствия, обнаружение сна при остановившемся performance.now, отказ от просроченных/некорректных образцов и сохранение карточки при недоступности времени.

Backend-проверки подтверждают отсутствие обращений к БД и Redis у GET /time при включённых аудитах и глобальном лимите, сохранение payload существующего ответа, добавление заголовков и документацию OpenAPI. Реальный сервер во время этих проверок не изменяется.

Результаты: три целевые backend-проверки прошли без запуска БД. Общий frontend-прогон — 254 успешных теста; после него добавлена и проверена ещё одна проверка неопределённого времени после сна при действующем ограничении повторов. Итого проверено 255 различных frontend-тестов; последний набор часов — семь успешных проверок, карточки — 15. TypeScript обоих приложений, обе production-сборки и prerender основного приложения успешны. git diff --check успешен.

# Обновление школы из заявки

В админ-панели «Школы» → заявка → «Обновить школу по ID»:

1. Ввести ID существующей школы и загрузить запись.
2. Проверить регион, название и количество привязанных пользователей.
3. Отредактировать данные из заявки: город, краткое и полное название, адрес, сайт, email.
   Отсутствующие в заявке полное название, адрес, сайт и email берутся из текущей записи.
4. Нажать «Проверить изменения» и сверить таблицу «Было / Станет».
5. Нажать «Подтвердить обновление и одобрить».

Школа обновляется без смены ID. Прежние пользователи остаются привязанными,
заявитель получает эту школу и её регион, заявка становится одобренной.
Город исправляется только в пределах региона существующей школы;
существующие города переиспользуются по нормализованному названию.
Признаки групп, активность, куратор и информация школы сохраняются.
Операция доступна только администратору и записывается в аудит.

API: `POST /api/v1/admin/school-submissions/{id}/approve` с единственным режимом
`update_school`. Обязательны `school_id`, `expected_updated_at` из GET школы,
`confirmed: true`, `city_name`, `short_name`, `full_name`, `address`, `url`;
`email` необязателен. Посторонние поля запрещены. Все изменения выполняются
в одной транзакции. Уже обработанная заявка или устаревшая версия школы
возвращают HTTP 409; при конфликте надо заново загрузить школу и сверить данные.

Для развёртывания обновить backend/API и сборку frontend админ-панели.
Миграция БД не требуется: используется существующее поле `schools.updated_at`.
